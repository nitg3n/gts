# 학교로GO Brand Design Guide

## 1. Brand Direction

학교로GO는 중학생이 고등학교를 선택할 때 필요한 정보를 한곳에서 이해하고, 자신의 선호와 상황에 맞는 선택지를 찾도록 돕는 서비스다.

브랜드 인상은 **친근하되 전문적인 Apple 스타일**을 기준으로 한다. 지나치게 교육청 포털처럼 딱딱하거나, 학원 광고처럼 과장된 느낌을 피한다. 사용자가 처음 접속했을 때는 "깔끔하고 믿을 수 있다", 설문과 추천 결과를 볼 때는 "내 선택을 차분하게 도와준다"는 인상을 줘야 한다.

핵심 키워드:

- 친근함: 학생과 학부모가 부담 없이 시작할 수 있는 말투와 밝은 여백
- 전문성: 공공 데이터, 위치, 설문, 리뷰가 신뢰감 있게 정리된 정보 구조
- 선명함: 한 화면에서 지금 무엇을 해야 하는지 바로 보이는 인터랙션
- 절제된 멋: 장식보다 타이포, 간격, 모션, 상태 표현으로 완성도 만들기

## 2. Logo

현재 로고 파일:

- `public/logo-black.svg`: 밝은 배경, 헤더, 일반 UI에서 사용
- `public/logo-white.svg`: 어두운 배경 또는 진한 이미지 위에서 사용

사용 규칙:

- 로고는 단독 아이콘으로도 인식 가능해야 하므로 주변 여백을 충분히 둔다.
- 헤더에서는 아이콘 32px, 텍스트 `학교로GO`와 함께 사용한다.
- 로고를 버튼, 배지, 카드 안에 반복적으로 남용하지 않는다.
- 로고 색상을 임의로 바꾸지 않는다. 필요하면 black/white 버전을 선택한다.

## 3. Color System

기본 팔레트는 `src/app/globals.css`의 CSS variable을 기준으로 한다.

| Token | Hex | Use |
| --- | --- | --- |
| `--background` | `#f5f5f7` | 전체 앱 배경 |
| `--foreground` | `#1d1d1f` | 본문/헤딩 기본 텍스트 |
| `--brand-primary` | `#468A57` | 브랜드 핵심색, 주요 CTA, 활성 상태, 핵심 정보 |
| `--brand-primary-dark` | `#356b43` | CTA hover, 진한 강조 |
| `--brand-primary-soft` | `#edf6ef` | 선택 상태 배경, 약한 강조 표면 |
| `--apple-blue` | `#468A57` | 기존 컴포넌트 호환용 alias. 새 코드에서는 `--brand-primary` 우선 |
| `--apple-blue-dark` | `#356b43` | 기존 컴포넌트 호환용 alias |
| `--apple-green` | `#34c759` | 성공, 승인, 긍정 상태 |
| `--apple-orange` | `#ff9f0a` | 거리, 주의, 보조 강조 |
| `--apple-red` | `#ff3b30` | 오류, 거절, 위험 상태 |
| `--apple-gray-1` | `#f5f5f7` | 약한 표면 배경 |
| `--apple-gray-2` | `#e8e8ed` | 섹션/패널 경계선 |
| `--apple-gray-3` | `#d2d2d7` | 입력/버튼 경계선 |
| `--apple-gray-4` | `#86868b` | 보조 라벨 |
| `--apple-gray-5` | `#6e6e73` | 설명문 |
| `--apple-ink` | `#0b0b0f` | 고대비 어두운 면 |

색상 원칙:

- 기본 화면은 흰색, 밝은 회색, 검정 텍스트 중심으로 유지한다.
- `#468A57`은 "주요 행동"과 "선택된 상태"에만 사용한다.
- 한 화면에서 강조색을 2개 이상 경쟁시키지 않는다.
- 교육 서비스라고 해서 여러 초록, 노랑, 원색을 많이 쓰지 않는다. 초록은 브랜드 핵심색 하나로 절제한다.
- 배경 장식은 약하게만 사용한다. 큰 그라디언트 덩어리나 장식용 원형 요소는 피한다.

## 4. Typography

기본 폰트:

```css
Arial, "Apple SD Gothic Neo", "Malgun Gothic", Helvetica, sans-serif
```

타이포 원칙:

- 헤딩은 굵고 짧게 쓴다. 예: `내게 맞는 학교로 가는 길.`
- 설명문은 넉넉한 line-height를 사용해 읽기 편하게 둔다.
- 버튼, 라벨, 배지는 `font-weight: 700~900` 범위로 선명하게 처리한다.
- letter-spacing은 0을 유지한다.
- 화면 너비에 따라 font-size를 무리하게 `vw`로 키우지 않는다.

권장 크기:

- Hero H1: desktop `56~72px`, mobile `40~48px`
- Page H1: `40~56px`
- Section title: `28~36px`
- Card title: `18~22px`
- Body: `15~18px`
- Caption/label: `12~14px`

## 5. Layout

기본 레이아웃 감각:

- 화면은 넓은 여백과 명확한 정보 덩어리로 구성한다.
- 첫 화면은 실제 기능이 바로 보이게 한다. 마케팅 랜딩처럼 설명만 있는 화면은 피한다.
- 지도, 학교 카드, 설문, 추천 결과는 모두 같은 제품 안에 있는 것처럼 보여야 한다.
- 주요 컨테이너 폭은 `max-w-7xl`을 기준으로 한다.
- 섹션은 full-width band 또는 unframed layout을 사용한다.

현재 공통 클래스:

- `.apple-page`: 전체 페이지 배경
- `.apple-section`: 상단 주요 섹션
- `.apple-panel`: 정보 패널
- `.apple-button-primary`: 주요 CTA
- `.apple-button-secondary`: 보조 CTA
- `.apple-eyebrow`: 작고 선명한 섹션 라벨

## 6. Components

### Header

- 항상 상단 sticky로 둔다.
- 배경은 `white/80 + backdrop-blur-xl`로 가볍게 처리한다.
- 로고와 서비스명은 왼쪽, 탐색 메뉴는 오른쪽에 둔다.
- 모바일에서는 nav label을 숨기고 icon 중심으로 유지한다.

### Buttons

Primary:

- 사용처: 내 위치로 보기, 추천 결과 보기, 비교 시작 같은 주요 행동
- 색상: `#468A57`
- 형태: pill, full rounded
- hover: 더 진한 브랜드 초록과 약한 translateY

Secondary:

- 사용처: 보조 이동, 설정, 로그인 등
- 색상: 흰색 반투명 배경 + 회색 border
- hover: 약한 브랜드 초록 tint

버튼 규칙:

- 아이콘이 있는 명령은 lucide icon을 함께 사용한다.
- 버튼 텍스트는 짧게 쓴다.
- 버튼 내부 텍스트가 줄바꿈으로 깨지지 않도록 최소 높이를 둔다.

### Cards

- 학교 카드는 반복 정보 단위로만 사용한다.
- 카드 안에 또 다른 큰 카드를 중첩하지 않는다.
- border는 `#e8e8ed`, 배경은 `white/90` 정도로 가볍게 둔다.
- hover는 이동감보다 신뢰감이 우선이다. `translateY(-1px)` 정도만 허용한다.

### Map

- 지도는 실제 기능 화면의 핵심 시각 요소다.
- 지도 컨테이너는 충분한 높이를 가져야 한다. 최소 360px.
- 마커는 학교 위치를 보여주고, 클릭 시 학교명이 나온다.
- 지도 키가 없거나 로딩 실패 시에도 사용자가 목록과 추천 흐름을 사용할 수 있어야 한다.

### Survey

- 길게 이어지더라도 각 질문은 명확한 패널로 분리한다.
- 선택지는 pill button 형태로 통일한다.
- 현재 선택 상태는 브랜드 초록으로 선명하게 보여준다.
- 위치 반영은 설문 흐름 중 별도 섹션으로 제공한다.

### Results

- 추천 결과는 순위, 매칭도, 이유, 거리 순서로 빠르게 스캔 가능해야 한다.
- Top match는 어두운 패널로 강하게 보여줄 수 있다.
- 추천 이유는 과장된 문구보다 선택 기준과 연결된 이유를 짧게 표시한다.

## 7. Motion And Interaction

모션은 "고급스럽고 빠른 반응"을 목표로 한다.

- hover transition: `160ms ease`
- 큰 애니메이션, 튀는 bounce, 과한 scale은 사용하지 않는다.
- 사용자가 클릭 가능한 요소를 바로 알 수 있게 hover/focus 상태를 둔다.
- 위치 조회, 추천 계산, 지도 로딩은 상태 문구를 즉시 바꿔준다.

## 8. Voice And Copy

문구 톤:

- 학생에게 친근하지만 유치하지 않게 말한다.
- 학부모에게도 신뢰가 가는 단어를 쓴다.
- "완벽한 학교"처럼 과장하지 않는다.
- "추천", "후보", "기준", "반영"처럼 판단의 근거가 느껴지는 단어를 사용한다.

좋은 예:

- `내게 맞는 학교로 가는 길.`
- `현재 위치 기준 주변 학교`
- `거리 선호와 선택한 기준을 반영했습니다.`
- `선택한 위치 주변 학교`

피해야 할 예:

- `인생을 바꿀 최고의 학교 추천`
- `무조건 여기 가세요`
- `AI가 완벽하게 골라드립니다`
- `엄청난 빅데이터 분석`

## 9. Service Trust

학교로GO는 추천 서비스이지만, 결정권을 대신 가져가면 안 된다.

표시 원칙:

- 사용자 화면에는 API, 저장소, 수집 경로 같은 구현 설명을 노출하지 않는다.
- 학교 후보, 추천 이유, 리뷰, 위치처럼 학생이 바로 이해할 수 있는 언어만 사용한다.
- 리뷰 데이터가 부족하면 부족하다고 말한다.
- 매칭도는 절대 점수가 아니라 현재 설문 조건에서의 상대적 추천 점수로 설명한다.

내부 운영 원칙:

- 외부 연동과 저장 방식은 서비스 내부 책임으로 다룬다.
- 사용자는 어느 시스템에서 가져왔는지보다 지금 무엇을 선택하면 되는지 먼저 볼 수 있어야 한다.
- 오류 상태도 개발자 설정이 아니라 사용자가 다시 시도할 수 있는 행동으로 안내한다.

## 10. Accessibility

- 텍스트와 배경의 대비를 충분히 유지한다.
- 아이콘 버튼에는 aria label 또는 보이는 텍스트를 함께 둔다.
- 브랜드 초록만으로 선택 상태를 전달하지 않는다. 형태, 굵기, 배경도 함께 바꾼다.
- 지도 없이도 목록과 추천 결과를 사용할 수 있어야 한다.
- 모바일에서 버튼과 선택지는 최소 40px 이상의 터치 영역을 둔다.

## 11. Do And Do Not

Do:

- 흰색/회색/검정 기반의 차분한 화면 위에 브랜드 초록으로 행동을 강조한다.
- 추천 상태와 다음 행동을 짧게 표시한다.
- 복잡한 정보를 순위, 카드, 표, 패널로 정리한다.
- 실제 기능을 첫 화면에 보여준다.

Do not:

- 교육 서비스라는 이유로 칠판, 연필, 노트 같은 장식을 반복하지 않는다.
- 카드 안에 카드, 패널 안에 패널을 계속 중첩하지 않는다.
- 보라색 그라디언트, 과한 그림자, 장식용 원형 배경을 남용하지 않는다.
- 추천 결과를 확정적인 진로 판단처럼 말하지 않는다.

## 12. Implementation Checklist

새 화면이나 컴포넌트를 만들 때 확인할 것:

- `globals.css`의 색상 토큰을 우선 사용했는가?
- 주요 행동은 `apple-button-primary`로, 보조 행동은 `apple-button-secondary`로 처리했는가?
- 텍스트가 모바일에서 잘리지 않는가?
- 지도와 추천 실패 상태가 사용자 행동 중심으로 안내되는가?
- 구현 방식이나 출처가 사용자 화면에 드러나지 않는가?
- 로고는 black/white 버전을 상황에 맞게 사용했는가?
- 기능 설명 문구가 화면을 불필요하게 채우지 않는가?
